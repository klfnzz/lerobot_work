一、整体闭环与架构说明
--------------------------------------------------------------------------------
1. 迭代闭环（DAgger / HG-DAgger / RaC 范式）：
   基础模型 v0（示教集训练）
     -> 真机部署 + 人工在即将失败时暂停并遥操恢复/纠偏（录制 DAgger 数据集）
     -> 移除 intervention 标记列并与原始示教数据集合并
     -> 在合并数据集上微调得到模型 v1
     -> 部署 v1 继续针对剩余失败模式采集纠偏（多轮迭代）

2. 本机 Pika + Piper 双环境解耦架构：
   - 终端 1（pika 环境，ROS 2 Humble / Python 3.10）：
     运行 `examples/piper/start_pika_teleop_bridge.bash`，拉起：
       (1) Vive 空间定位节点 `pika_single_locator_node`（发布 `/pika_pose`）
       (2) Pika 串口夹爪与按键节点 `serial_gripper_imu`（默认 `/dev/ttyUSB50`）
       (3) Pinocchio + CasADi 6 轴逆解 TCP 桥接服务 `pika_teleop_bridge.py`（监听 127.0.0.1:18765）
     注：桥接端【绝不占用】`can0` 与任何 RealSense 相机。
   - 终端 2（lerobot_piper 环境，Python 3.12）：
     运行 `lerobot-rollout --strategy.type=dagger --teleop.type=pika_leader ...`
     独占控制 `can0` 上的 Piper 从臂与 RealSense 相机；每次进入纠偏（或按 Pika 手柄按键）
     都会自动读取 Piper 当前真实关节角做零跳变重锚定，无需预先对齐手部位置。

--------------------------------------------------------------------------------
【必看参数规则】
1. `--dataset.repo_id` 的名称部分必须以 `rollout_` 开头（如 `${HF_USER}/rollout_piper_dagger_pi05`）。
2. `--dataset.fps` 必须与 `--fps` 完全相等（且后续要合并的原数据集也必须是相同 fps 和相同相机）。
3. `--dataset.no_stamp=true` 用于固定目录与仓库名；若去掉该参数，系统会自动追加 `_YYYYMMDD_HHMMSS`。
   若保留 `--dataset.no_stamp=true` 且目录已存在，续采请追加 `--resume=true`，或更换 `repo_id`/`root`。
4. 录制模式选择：
   - 默认（`--strategy.record_autonomous=false`）：只录制人工纠偏段，每次按 Tab 开始到再按 Tab 结束存为 1 条 episode（最适合直接合并微调）。
   - 全程连续录制（追加 `--strategy.record_autonomous=true`）：策略自主帧（`intervention=False`）与人工纠偏帧（`intervention=True`）全部录制，按视频文件大小自动切分 episode。

================================================================================
五、第 3 步：采集现场交互按键与标准动作规范
================================================================================
状态机流转：
  AUTONOMOUS（策略自主控制）
      <---[ Space ]---> PAUSED（策略暂停，机械臂位置保持，不录帧）
                            <---[ Tab ]---> CORRECTING（Pika 遥操纠偏，实时录帧）

具体操作步骤：
1. 【观察自主执行】（AUTONOMOUS）：
   启动后策略开始自动控制 Piper。手持 Pika 保持自然舒适姿势即可（此时 Pika 不会控制机械臂）。

2. 【发现异常立即暂停】（按 `Space` -> 进入 PAUSED）：
   当看到机械臂即将抓空、碰撞、犹豫卡住或偏离轨迹时，按一下 `Space`。
   策略暂停，Piper 保持当前关节姿态不动，此阶段不录制任何帧。

3. 【接管并录制恢复+纠偏】（按 `Tab` -> 进入 CORRECTING）：
   手握好 Pika 后按一下 `Tab`：
   - 系统自动将当前手部姿态与机械臂当前姿态零偏差锚定，机械臂不会产生任何跳变；
   - 先做 Recovery（把机械臂从危险/偏离位姿拉回正常的分布内状态）；
   - 再做 Correction（干净、果断地演示正确的抓取/放置动作，避免多余晃动）；
   - 【空间离合技巧】：如果遥操中途手臂伸展到了不舒服的边界，按一下 **Pika 手柄上的物理按键**
     即可松开空间离合（机械臂原地不动），把手收回舒适区后再按一下 **Pika 手柄按键** 即可无缝继续！
   - 【丢帧保护】：若 Vive 定位短暂被遮挡超过 0.5 秒，机械臂会自动驻留并在信号恢复时重新锚定，不会飞车。

4. 【结束本段纠偏】（再次按 `Tab` -> 回到 PAUSED）：
   纠偏完成后按一下 `Tab`，当前纠偏窗口立即保存为 1 条独立 episode（终端提示 `Correction X/N saved`）。

5. 【交还策略继续运行】（按 `Space` -> 回到 AUTONOMOUS）：
   按 `Space` 让策略从纠正后的当前状态继续自主执行（无需重置回初始位）；同一局内可反复介入多次。
   如果当前任务已经彻底完成，也可以在 PAUSED 状态下先把桌面物体复位，再按 `Space` 让策略跑下一轮。

6. 【结束整个采集会话】（按 `ESC`）：
   采集满目标条数会自动退出；也可随时按 `ESC` 提前结束，程序会自动完成视频编码、数据集 finalize，
   并将 Piper 平滑移回停机安全位后失能断开。

七、第 5 步：数据集后处理（移除 intervention 列 + 与原始数据集合并）
================================================================================
DAgger 生成的数据集多了一列布尔特征 `intervention`。合并数据集要求两侧特征列表、相机名称与
`fps` 完全一致，因此先移除 `intervention` 列，再与原始示教集（或上一轮合并集）执行 `merge`：

# 1. 移除 intervention 特征列
lerobot-edit-dataset \
  --repo_id=${HF_USER}/rollout_piper_dagger_pi05 \
  --root=outputs/datasets/rollout_piper_dagger_pi05 \
  --new_repo_id=${HF_USER}/piper_dagger_round1_clean \
  --new_root=outputs/datasets/piper_dagger_round1_clean \
  --operation.type=remove_feature \
  --operation.feature_names="['intervention']" \
  --push_to_hub=false

# 2. 与原始示教数据集合并（注意两者的相机配置和 fps 必须一致！）
lerobot-edit-dataset \
  --new_repo_id=${HF_USER}/piper_demo_plus_dagger_r1 \
  --new_root=outputs/datasets/piper_demo_plus_dagger_r1 \
  --operation.type=merge \
  --operation.repo_ids="['${HF_USER}/piper_pick_and_place', '${HF_USER}/piper_dagger_round1_clean']" \
  --operation.roots="['outputs/datasets/piper_pick_and_place', 'outputs/datasets/piper_dagger_round1_clean']" \
  --push_to_hub=false

# （若进行第 2 轮、第 3 轮 DAgger，可把全部历史轮次一起列进 repo_ids 和 roots 合并）

九、常见报错速查
================================================================================
1. `Cannot communicate with Pika teleop bridge at 127.0.0.1:18765`
   -> 终端 1 未启动桥接脚本，先运行 `bash examples/piper/start_pika_teleop_bridge.bash`。

2. `Dataset names for rollout must start with 'rollout_'`
   -> `--dataset.repo_id` 斜杠后的名字必须以 `rollout_` 开头，例如 `lazycc/rollout_piper_dagger`。

3. `--dataset.fps (30) must equal --fps (10)`
   -> 同时传入相同的 `--fps` 与 `--dataset.fps`（10 Hz 模型都填 10，30 Hz 模型都填 30）。

4. `FileExistsError`（输出数据集目录已存在）
   -> 若想接着往同一个目录续采，追加 `--resume=true`；若想新开一轮采集，更换 `--dataset.repo_id`
      和 `--dataset.root`（或去掉 `--dataset.no_stamp=true`）。

5. 合并数据集时报特征或 FPS 不匹配
   -> 确认已先执行 `remove_feature` 删除 `['intervention']`，且 DAgger 采集时的 `--robot.cameras`、
      `--fps` 与原始示教数据集一致（例如原始集是 30 Hz 三相机，则采集也必须用 30 Hz 三相机；原始集是
      10 Hz 双相机，则采集也用 `$PIPER_MODEL_CAMERAS` + 10 Hz）。
